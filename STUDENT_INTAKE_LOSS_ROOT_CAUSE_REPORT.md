# Student Intake Loss Root Cause and Fix Report

## Executive Summary

The root cause of student intake loss was a **complete mismatch between frontend intake generation and production database structure**. The frontend was generating intake options using JavaScript date logic instead of loading from the production `intakes` table, and the backend was not resolving intake text to intake IDs before database storage.

## Root Cause Analysis

### 1. Database Schema Investigation

**Supabase users table contains:**
- `intake` (integer, nullable) - stores intake ID as foreign key
- `intake_year` (integer, nullable) - stores intake year separately

**Supabase intakes table contains:**
- `id` (integer, primary key)
- `name` (text, e.g., "JANUARY 2025", "MAY 2026")
- `year` (integer, e.g., 2025, 2026)
- `status`, `description`, `start_date`, `end_date`

**Production intakes available:**
```json
[
  {"id": 2, "name": "Test Intake 2026", "year": 2026},
  {"id": 3, "name": "january 2026", "year": 2026},
  {"id": 4, "name": "MAY 2026", "year": 2026},
  {"id": 5, "name": "JANUARY 2025", "year": 2025}
]
```

### 2. Frontend Issue

**File:** `frontend/assets/js/js/admin-dashboard.js`

**Problem:** The frontend was generating intake options using JavaScript:
```javascript
const currentYear = new Date().getFullYear();
const months = ['January', 'May', 'September'];
let intakeOptions = '';
for (let year = currentYear - 1; year <= currentYear + 2; year++) {
    months.forEach(month => {
        intakeOptions += `<option value="${month} ${year}">${month} ${year}</option>`;
    });
}
```

**Impact:**
- Generated options like "January 2026", "May 2026" did not match production intake names
- Frontend sent intake text like "January 2026" to backend
- Backend expected intake ID but received text

### 3. Backend Issue

**File:** `backend/controllers/studentController.js`

**Problem:** The `createStudent` and `updateStudent` functions were not:
1. Receiving the `intake` field from frontend
2. Resolving intake text to intake IDs
3. Properly storing the intake ID in the database

**Original code:**
```javascript
const {
  full_name, email, student_number, password, phone, gender,
  national_id, date_of_birth, address, guardian_name, guardian_phone,
  intake_year, course_id  // Missing 'intake' field
} = req.body;

const studentData = {
  // ...
  intake_year,  // Only stored year, not intake ID
  course_id,
  status: 'active'
};
```

### 4. Data Flow Breakdown

**Incorrect flow (before fix):**
```
Frontend: "January 2026" (generated by JS)
↓
Backend: Not received, not resolved
↓
Database: intake=null, intake_year=null
```

**Correct flow (after fix):**
```
Frontend: "JANUARY 2025" (loaded from production intakes)
↓
Backend: Resolve "JANUARY 2025" → intakes.id=5
↓
Database: intake=5, intake_year=2025
```

## Fixes Applied

### 1. Frontend Fix

**File:** `frontend/assets/js/js/admin-dashboard.js`

**Changes:**
- Modified `addStudentBtn` click handler to load intakes from production
- Modified `editStudent` function to load intakes from production
- Changed from JavaScript-generated options to API-loaded options

**New code:**
```javascript
// Load actual production intakes
let intakeOptions = '<option value="">Select Intake</option>';
try {
    const intakes = await apiRequest('/intakes');
    intakes.forEach(intake => {
        intakeOptions += `<option value="${intake.name}">${intake.name}</option>`;
    });
} catch (error) {
    console.error('Failed to load intakes:', error);
}
```

### 2. Backend Student Creation Fix

**File:** `backend/controllers/studentController.js`

**Changes:**
- Added `intake` field to destructuring
- Added intake resolution logic using Intake model
- Store resolved intake ID and year in database
- Added detailed logging

**New code:**
```javascript
const {
  full_name, email, student_number, password, phone, gender,
  national_id, date_of_birth, address, guardian_name, guardian_phone,
  intake, intake_year, course_id  // Added 'intake' field
} = req.body;

// Resolve intake text to intake ID
let resolvedIntakeId = null;
let resolvedIntakeYear = null;

if (intake) {
  const Intake = require('../models/Intake');
  const allIntakes = await Intake.findAll({});

  const normalizedIntake = intake.toString().trim().toUpperCase();
  const matchedIntake = allIntakes.find(i =>
    i.name && i.name.toUpperCase() === normalizedIntake
  );

  if (matchedIntake) {
    resolvedIntakeId = matchedIntake.id;
    resolvedIntakeYear = matchedIntake.year;
  }
}

const studentData = {
  // ...
  intake: resolvedIntakeId, // Store intake ID
  intake_year: resolvedIntakeYear, // Store intake year
  course_id,
  status: 'active'
};
```

### 3. Backend Student Update Fix

**File:** `backend/controllers/studentController.js`

**Changes:**
- Added same intake resolution logic to `updateStudent` function
- Added detailed logging for debugging

**New code:**
```javascript
// Resolve intake text to intake ID if provided
let resolvedIntakeId = null;

  }

const updateData = {
  // ...

```

## Final Architecture

```
intakes table (Supabase)
├── id (primary key)
├── name (e.g., "JANUARY 2025")
└── year (e.g., 2025)
         ↓
users table (Supabase)
├── intake (foreign key to intakes.id)
├── intake_year (denormalized year)
└── student_number (primary identity)
         ↓
Student API (POST /api/students, PUT /api/students/:id)
↓
Frontend (admin-dashboard.js)
├── Loads intakes from /api/intakes
└── Sends intake text to backend
```

## Root Cause Summary

**Primary root cause:** Frontend generated intake options using JavaScript instead of loading from production database, and backend did not resolve intake text to intake IDs.

**Secondary root cause:** Backend student creation/update functions did not include intake field in destructuring and lacked intake resolution logic.

**Impact:** All manual student creation and editing lost intake data, while Excel imports worked correctly.

**Fix:** Both frontend and backend now use production intakes as the single source of truth, with proper text-to-ID resolution.
